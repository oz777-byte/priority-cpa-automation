# Deployment — העלאה לדומיין

**מצב נוכחי**: האתר בנוי ונבנה בהצלחה — 100 עמודים סטטיים. הוא **לא נפרס** כי אין לי את הדומיין שלך ואין לי גישה לחשבון Vercel שלך.

מה שנשאר הוא שלושה צעדים של העתק-הדבק, כ-15 דקות.

---

## מצב תצוגה מקדימה — למה זה ברירת המחדל

האתר עולה במצב `preview` עד שחשבון השותפים מחובר. במצב הזה:

| | |
|---|---|
| באנר עליון | "תצוגה מקדימה — הקטלוג הוא נתוני דוגמה" |
| `robots.txt` | `Disallow: /` |
| תג meta | `noindex, nofollow` |
| כפתורי רכישה | **לא נרנדרים כלל** — במקומם מוצג ה-SubID שייווצר |

**זה לא זהירות יתר.** קטלוג הדוגמה מכיל מחירים שאינם אמיתיים. אתר שמציג אותם כמחירים אמיתיים לקונה הוא הטעיית צרכן, ואינדוקס שלו בגוגל יקשור את הדומיין לתוכן שגוי עוד לפני שהוא התחיל. המעבר ל-`live` הוא משתנה סביבה אחד — אחרי שהמפתחות אמיתיים ואחרי שקליק בדיקה אומת בדוח ההזמנות.

## שלב 1 · דומיין

קנה דומיין (Namecheap / Cloudflare / GoDaddy). המלצה: `.com` באנגלית, תוכן בעברית.

**אל תפנה DNS עדיין** — Vercel ייתן לך את הרשומות המדויקות בשלב 3.

---

## שלב 2 · פרויקט Vercel

הריפו כבר מחובר ל-Vercel עבור פרויקט Priority CPA. החנות היא **פרויקט נפרד באותו ריפו** — לא לגעת בקיים.

1. Vercel → **Add New → Project** → בחר `oz777-byte/priority-cpa-automation`
2. **Root Directory**: `affiliate-engine/code`
   ה-`vercel.json` שם כבר מגדיר build command, output directory וכותרות אבטחה.
3. **Environment Variables** — הדבק:

```
NEXT_PUBLIC_SITE_URL      = https://הדומיין-שלך.com
NEXT_PUBLIC_SITE_NAME     = OS Tech Ventures
NEXT_PUBLIC_DATA_MODE     = preview
NEXT_PUBLIC_CONTACT_EMAIL = המייל-שלך
```

4. **Deploy**

⚠️ `NEXT_PUBLIC_SITE_URL` חייב להיות מדויק וללא `/` בסוף. הוא מזין canonical URLs ואת ה-sitemap — ערך שגוי מרעיל בשקט כל אות SEO באתר.

---

## שלב 3 · חיבור הדומיין

Vercel → הפרויקט → **Settings → Domains** → הוסף את הדומיין.
Vercel יציג רשומת `A` או `CNAME` — הדבק אותה אצל רשם הדומיין. תעודת SSL נוצרת אוטומטית תוך דקות.

## מה עולה לאוויר

| נתיב | תוכן |
|---|---|
| `/` | עמוד בית עם כל הקטגוריות ומספר המוצרים בכל אחת |
| `/cases/iphone` וכו' | ~95 עמודי קטגוריה ודגם |
| `/disclosure` | גילוי נאות |
| `/privacy` | מדיניות פרטיות |
| `/terms` | תנאי שימוש |
| `/sitemap.xml`, `/robots.txt` | נבנים אוטומטית לפי מצב האתר |

שלושת עמודי המשפט אינם מילוי — הם נדרשים לפני שאתר מסחרי מקבל מבקר ראשון בישראל. נוסחו בהתאם.

## מעבר ל-live

לאחר אישור חשבון השותפים:

1. ב-Vercel הוסף:
   ```
   ALIEXPRESS_APP_KEY      = ...
   ALIEXPRESS_APP_SECRET   = ...
   ALIEXPRESS_TRACKING_ID  = ...
   ```
2. **צור לינק אחד בפורטל וקרא ממנו את שם פרמטר ה-SubID** ← החוליה הקריטית
3. עדכן את הפרופיל ב-`packages/skills/link-builder/src/networks.ts` וסמן `verified: true`
4. קליק בדיקה → אימות שה-SubID מופיע בדוח ההזמנות
5. **רק אז** שנה `NEXT_PUBLIC_DATA_MODE` ל-`live` והפעל deploy מחדש

הסדר חשוב. מעבר ל-`live` לפני שלב 4 פירושו אתר מאונדקס עם לינקים שלא נספרים — כלומר תנועה שנשרפת בלי דרך לדעת שזה קרה.

## בנייה מקומית

```bash
cd affiliate-engine/code
npm install
cp .env.example .env.local        # ערוך את NEXT_PUBLIC_SITE_URL
npm run dev:storefront            # http://localhost:3000
npm run build:storefront          # ייצוא סטטי ל-apps/storefront/out
```

## מה עדיין לא קיים

| רכיב | סטטוס |
|---|---|
| סנכרון קטלוג אוטומטי | לא נבנה — הקטלוג נבנה בזמן build |
| שירות redirect `/go/{slug}` | לא נבנה — נדרש לרישום קליקים |
| קונסולת ההחלטות כאתר | קיימת כאב-טיפוס בלבד |
| Proxy לתמונות | לא נבנה — כרגע אייקון קטגוריה במקום תמונה |

הפער האמיתי הוא **שירות ה-redirect**: בלעדיו לינק נספר ע"י המרקטפלייס אבל לא אצלנו, כלומר יש עמלות ואין EPC לכל עמוד. זה הצעד ההנדסי הבא.
