## רכיבים מפורטים

### Header (top bar)
- **חזרה**: ← ל-queue
- **breadcrumb**: company / invoice number
- **שמור** — שמור as draft (לא מאושר עדיין)
- **אשר** — סופי, עובר ל-batch לייצוא

### PDF Viewer (50% מהמסך)
- **Zoom**: 50%, 75%, 100%, 150%, fit-to-width
- **Pages**: ניווט אם רב-עמודי
- **Highlights**: שדות שזוהו אוטומטית מסומנים בצהוב (mouseover → tooltip "OCR confidence: 94%")
- **Selection**: מאפשר ל-CPA לסמן טקסט ב-PDF → אם הוא מאמין שמה שהמערכת חילצה שגוי, יכול להעתיק את הטקסט הנכון

### Invoice Details Panel (top right)
- **ספק**: שם, ע.מ, קוד פנימי. ✓ ירוק = matched. ⚠ צהוב = needs review.
- **שינוי ספק**: אם המערכת זיהתה שגוי, פותח dialog לבחירת ספק נכון או יצירת חדש
- **מספר חשבונית**: editable
- **תאריך**: editable עם date picker
- **סטטוס**: 🟢 מאושר / 🟡 ממתין / 🔴 שגיאה / ⚪ טיוטה

### Amounts Box
- **סכום לפני מע"מ**: editable
- **מע"מ rate**: dropdown (0%, 17%, 18%) — auto-detected מהתאריך
- **מע"מ amount**: auto-calculated (אבל editable)
- **סה"כ**: auto, או manual override

### JE Lines Table
- **גמיש**: הוסף/הסר שורות (לתרחישים מורכבים)
- **כל שורה ניתנת לעריכה**:
  - חשבון: autocomplete מ-master accounts
  - שם חשבון: auto-filled מהבחירה
  - חובה/זכות: D / C dropdown
  - סכום: numeric input
  - פעולות: edit (inline) / delete

- **מאזן בזמן אמת**: מתחת לטבלה — סך חובה = סך זכות (אם לא — אדום)
- **שחזר אוטומטי**: כפתור "🔄" — חוזר להצעה המקורית של המערכת אם CPA עשה שינויים

### Validation Status Panel
10 בדיקות מ-`05_domain/je_scenarios_playbook.md`:
- ✅ ירוק — עובר
- ⚠️ צהוב — אזהרה (אפשר להמשיך, אבל בודק)
- 🚫 אדום — חוסם (אסור לאשר עד שתוקן)
- כל בדיקה ניתנת ללחיצה → הסבר מלא

### Additional Fields
- **סוג תנועה**: ברירת מחדל "מ", dropdown לכל סוגי התנועה הפעילים בחברה
- **אסמכתא 1, 2, 3**: text fields
- **פרטים**: text (default "קניות" או מהמערכת)
- **מרכז עלות**: dropdown אם פעיל בחברה
- **מספר הקצאה**: auto-filled אם זוהה ב-OCR

## Interactions

### Standard Flow (95% מהזמן)
1. CPA פותח חשבונית → JE מוכן ומאוזן
2. סקירה ויזואלית של PDF + JE
3. Validation status — הכל ירוק
4. **לחיצה אחת על "אשר"** → JE עובר ל-pending batch
5. אוטומטית עובר לחשבונית הבאה (אם יש)

### Edit Flow
1. CPA רוצה לשנות חשבון בשורה 1
2. דבל-קליק על תא חשבון → autocomplete dropdown
3. בוחר חשבון אחר → רענן שם חשבון אוטומטית
4. אם השינוי חשוב (זה מקרה חוזר) → "שמור כחוק לעתיד" checkbox

### Add Line Flow
1. תרחיש מורכב — צריך 4 שורות במקום 3
2. לחיצה "➕ הוסף שורה"
3. שורה חדשה מתווספת בסוף
4. בוחר חשבון, ח/ז, סכום
5. המאזן מתעדכן בזמן אמת

### Reject Flow
1. CPA רואה שזה לא חשבונית עסקית (אישית, או של חברה אחרת)
2. כפתור [✕ דחה] (לא מופיע ב-mockup, אבל קיים בתפריט actions)
3. dialog: "למה דוחה?" → notes + categorize
4. החשבונית עוברת ל-rejected, לא נכנסת ל-batch

## Edge Cases

- **CPA פותח חשבונית שכבר אושרה**: read-only mode, [📤 ערוך מחדש] להחזיר ל-draft
- **חשבונית עם OCR confidence < 50%**: דגל אדום גדול "מומלץ לבדוק ידנית"
- **מספר ספקים אפשריים (fuzzy match)**: dropdown של top 5 + "צור חדש"
- **חשבונית בשפה אחרת (אנגלית)**: הצג גם תרגום + flag
- **חשבונית עם blank PDF**: error state "לא ניתן לחלץ — העלה מחדש או הזן ידנית"
